# 4. Процесс, инструменты, сборка

## Стек

| Компонент | Выбор | Почему |
|---|---|---|
| Движок | Unity 6 LTS | Основной язык C#, чего и требует курс |
| Рендер | URP | Единственный разумный вариант для мобильного VR |
| VR | OpenXR + XR Interaction Toolkit 3.x | Одна кодовая база под разные шлемы |
| Тесты | Unity Test Framework, NUnit | Встроен, ничего ставить не надо |
| Разработка без шлема | XR Device Simulator | Снимает зависимость от наличия устройства |
| Версионирование | Git + Git LFS | LFS обязателен для моделей, текстур, звука |

Целевая платформа фиксируется в первую неделю и больше не меняется. Автономный шлем
и настольный VR — это разные бюджеты производительности, и переезд в середине семестра
съест спринт целиком.

## Git в Unity: как не потерять работу

Unity-проекты ломаются в команде по одной причине — конфликты в сценах и префабах,
которые не сливаются вручную. Меры принимаются заранее, а не после первой потери.

**Настройки проекта, обязательные с первого коммита.** Форсировать текстовую сериализацию
(`Editor Settings → Asset Serialization → Force Text`), включить видимые meta-файлы,
подключить UnityYAMLMerge как merge-драйвер для `.unity` и `.prefab`.

**Одна головоломка — один префаб.** Сцена комнаты содержит только расставленные экземпляры
префабов. Разработчик головоломки правит свой префаб, а не сцену. Это убирает девять из
десяти конфликтов.

**Сцену правит один человек за раз.** Право на редактирование `Room.unity` берётся явно,
в чате команды. Звучит бюрократично, экономит вечер каждому.

**Ветки.** `main` защищена, слияние только через PR. Ветки вида `feature/safe-puzzle`,
`fix/teleport-on-stairs`. Живут не дольше нескольких дней: чем дольше ветка, тем больнее слияние.

**Git LFS** на `*.fbx *.png *.tga *.psd *.wav *.mp3 *.mp4`. Настраивается до первого
коммита ассетов, иначе история распухнет безвозвратно.

**Не коммитим** `Library/`, `Temp/`, `Logs/`, `Build/`, `UserSettings/`. Стандартный
`.gitignore` для Unity берётся с github/gitignore и правится под проект.

## Ассеты: где брать и как не утонуть

Правило: команда не моделирует ничего, кроме предметов, которых нельзя найти готовыми.
Время на моделирование — время, не потраченное на код, а оценивают код.

Бесплатные источники: Kenney, Poly Pizza, Quaternius, Sketchfab с фильтром по лицензии CC0,
секция Free на Unity Asset Store, Mixamo для анимаций, Freesound для звука.

Каждый внешний ассет заносится в `docs/assets-credits.md`: что, откуда, лицензия.
На защите за это спросят, и делать этот список в последнюю ночь мучительно.

Единый стиль важнее качества отдельной модели. Разнородные ассеты выглядят хуже,
чем стабильно средние. Помогает общая палитра и один набор материалов на всю комнату.

## Производительность

Для автономного шлема бюджет жёсткий, и проверять его надо с первого спринта, а не в конце:

- Частота кадров не ниже 72 герц, без единичных просадок в момент решения головоломок.
- Вызовы отрисовки — порядка сотни на кадр. Достигается атласами и статическим батчингом.
- Освещение запечённое. Динамических источников не больше двух, и только там, где без них
  не обойтись, например мигающая лампа при подаче питания.
- Стерео-рендеринг в режиме Single Pass Instanced.
- Профилировать на устройстве, а не в редакторе. Показания редактора не имеют отношения
  к реальности.

## Тестирование

**Юнит-тесты (EditMode).** Доменный и прикладной слои. Бегут за секунды, гоняются
на каждом коммите. Список того, что покрывается, — в документе по архитектуре.

**Интеграционные тесты (PlayMode).** Немного, штук пять: сцена грузится, сервисы поднимаются,
сохранение переживает перезагрузку сцены, комната проходится программно без участия рук.
Последний тест бесценен: он ловит поломку цепочки за секунды вместо десяти минут в шлеме.

**Ручной чек-лист перед сдачей спринта.** Один лист, проходится в шлеме:
предметы берутся обеими руками, ничего не проваливается сквозь геометрию, телепорт не
выносит за стены, интерфейс читается, звук слышен, выход и перезапуск работают.

**Пользовательское тестирование.** Начиная с третьего спринта, каждый спринт минимум
один человек со стороны. Правила: не подсказывать, засекать время, записывать все места
застревания. Телеметрия делает это автоматически, но живое наблюдение показывает то,
чего в логах нет.

## Автоматизация

Если есть возможность, поднять простой CI на GitHub Actions с прогоном EditMode-тестов
на каждый PR. Ночная сборка на платформу — приятный бонус, но требует лицензии в CI
и настройки, поэтому это задача на середину семестра, а не на первую неделю.

Как минимум — pre-commit проверка форматирования и запрет коммита в `main` напрямую.
